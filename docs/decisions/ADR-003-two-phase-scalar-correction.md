# ADR-003 — Двухфазная скалярная коррекция в `CovarianceRepresentation`

Дата: 2026-09-11. Статус: принято.

## Контекст

Исходный проектный документ задавал `correctScalar(array $h, float $r): array{0: float, 1: list<float>}`,
возвращающий `[s, phi]` и, как следует из названия, применяющий коррекцию.
Но §2.8 требует, чтобы отвергнутое гейтом измерение **не меняло ни x̂, ни P**,
а Huber-взвешивание меняет эффективную `r` уже *после* того, как известна невязка.
Решение принять/отвергнуть/взвесить нужно принимать между вычислением `s`
и обновлением `P`. Одновызовный `correctScalar` этого не позволяет.

Кроме того, возврат массива `[s, phi]` — аллокация на каждый канал каждого шага,
что противоречит §0.2 п.12 (нулевые аллокации в горячем цикле).

## Решение

```php
$s   = $rep->prepareScalar($h, $r);   // phi = P·hᵀ, s = h·phi + r; P не тронута
$phi = $rep->gain();                  // внутренний буфер, K = phi / s
// ... гейт по innovation²/s, вычисление r_eff для Huber ...
$rep->commitScalar($rEff);            // P ← P − phi·phiᵀ / (h·phi + r_eff)
```

- `prepareScalar` возвращает скаляр `s`, `phi` пишется в предвыделенный буфер.
- `gain()` отдаёт этот буфер без копирования (refcount), только для чтения.
- `commitScalar(float $r)` применяет отложенное обновление. Для UD-формы (Бирман)
  между фазами хранятся `f = Uᵀhᵀ`, `v = D·f` — представление владеет scratch-состоянием.
- Отвергнутое измерение — `prepareScalar` без `commitScalar`.

## Последствия

- Все четыре формы (Sequential, Joseph, UD, SquareRoot) реализуют один протокол.
- Нельзя вызывать `prepareScalar` дважды без `commitScalar` для одного и того же
  канала, ожидая накопления — это не ошибка, а просто отбрасывание первой подготовки.
- `KalmanFilter` — единственный вызывающий; пользователи библиотеки этот интерфейс
  напрямую не используют.
