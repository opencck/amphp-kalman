# ADR-005 — Чистые «выносимые» функции и тег `@offloadable`

Дата: 2026-09-11. Статус: принято.

## Контекст

Владелец проекта планирует топологию «приложение-продьюсер → брокер очередей →
консьюмер → канал (HTTP-запрос к приложению с результатом) → приложение».
Для этого тяжёлые по времени математические операции должны быть выделены в
функции, которые можно вычислить в другом процессе / на другой машине, а результат
вернуть по сети. Такие функции должны быть **чистыми**: результат зависит только
от аргументов, аргументы и результат сериализуемы (скаляры и массивы), никаких
объектов с состоянием, замыканий, ссылок на соединения.

Одновременно §0.2 п.12 требует нулевых аллокаций в горячем цикле `predict/correct`
внутри процесса. Чистые функции, возвращающие новые массивы, этому противоречат.

## Решение

Два уровня API для одной математики:

1. **Горячий путь in-process** — объект `KalmanFilter` + `CovarianceRepresentation`,
   изменяет буферы на месте, нулевые аллокации. Для задержки в микросекунды.

2. **Чистые статические функции** — помечены в phpdoc тегами
   ```
   @deterministic
   @offloadable
   ```
   Контракт `@offloadable`:
   - метод `public static`;
   - все параметры — `int|float|string|bool|array` (массивы рекурсивно из того же),
     `null` допустим;
   - возвращаемое значение — того же класса типов;
   - нет обращений к статическому состоянию, времени, I/O, генераторам случайных чисел
     без явного seed в аргументах;
   - детерминирован: одинаковые аргументы → побитово одинаковый результат.

   Проверяется `ArchitectureTest::testOffloadableMethodsArePureStaticAndSerializable`
   через Reflection (статичность, типы параметров и возврата).

Выделенные `@offloadable` функции (по мере фаз):

| Функция | Что считает | Фаза |
|---|---|---|
| `Linalg\Flat::*`, `Linalg\Cholesky::*` | базовая линейная алгебра | 1 |
| `Filter\FilterBatch::run(modelConfig, filterConfig, snapshot, ticks)` | прогон пачки измерений из заданного состояния → новое состояние + статистика | 1 |
| `Discretization\VanLoan::discretize(A, G, Qc, dt, n)` | F(dt), Q(dt) через матричную экспоненту | 3 |
| `Discretization\ClosedForm::*` | аналитические F, Q | 3 |
| `Linalg\MatrixExponential::compute(M, n)` | exp(M) | 3 |
| `Diagnostics\SteadyStateSolver::dare(F, Q, H, R, n, m)` | установившаяся P и K | 3 |
| `Diagnostics\ObservabilityCheck::rank(F, H, n, m)` | ранг матрицы наблюдаемости | 3 |
| `App\Calibration\InnovationLikelihood::evaluate(modelConfig, theta, ticks)` | ℓ(θ) по истории | 5 |
| `Smoothing\RauchTungStriebel::smooth(trajectory)` | обратный проход RTS | 6 |
| `App\Calibration\ExpectationMaximization::mStep(...)` | замкнутые формулы Q̂, R̂ | 6 |

`Infrastructure\Task\*` (amphp/parallel) — это тонкие обёртки над этими же функциями:
`LikelihoodTask::run()` вызывает `InnovationLikelihood::evaluate()`. Любой другой
транспорт (RabbitMQ/Redis Streams консьюмер + HTTP-ответ) вызывает те же функции
с теми же массивами — библиотека транспорт не навязывает.

## Последствия

- Каждая `@offloadable` функция имеет тест «результат совпадает с in-process объектом
  побитово» (для `FilterBatch`) или с эталоном.
- Сериализуемая конфигурация моделей (`SerializableModel::toArray/fromArray` +
  `ModelRegistry`) появляется уже в фазе 1, а не в фазе 5, как в исходном плане.
