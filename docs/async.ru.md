# Асинхронный слой (AMPHP v3)

*English version: [async.md](async.md).*

Сам фильтр — синхронный PHP: шаг это несколько микросекунд арифметики без
всякого I/O. Всё асинхронное живёт *вокруг* него в `src/Infrastructure` —
фиды, очереди, сессии, вывод, воркеры — и никогда внутри шага. Этот документ
описывает топологию и правила, которые удерживают её корректной.

## 1. Топология одного процесса

```
  WS биржа A ─┐
  WS биржа B ─┼─► fiber'ы WebsocketFeed ─► Queue<Measurement> ─► ReorderBuffer ─► FilterSession (fiber-владелец)
  WS биржа C ─┘        (IngestOrchestrator)                                              │
                                                                                         ├─► Queue<StateSnapshot> ─► SnapshotBroadcaster (WebSocket-шлюз)
  BarClock (Interval) ──► Measurement::blind ───────────────────────────────┘           ├─► FilePersister / RedisPersister
                                                                                         └─► ConsistencyMonitor → алерты
```

Один event loop, ноль блокирующих вызовов, фильтром владеет один fiber.
Пропускная способность ограничена арифметикой шага; loop добавляет около
1 мкс на тик (`EventLoopOverheadBench`) или 0 мкс при батчинге (§5).

## 2. Ингест: WebSocket → Queue с back-pressure

`Infrastructure\Ingest\WebsocketFeed` подключается через `Rfc6455Connector`,
принимает кадры с `TimeoutCancellation(staleAfterSeconds)`, скомбинированным
с внешней отменой, декодирует каждый кадр через `MessageDecoder` и кладёт
`Measurement` в общую `Queue`.

- **Back-pressure бесплатен.** Если `FilterSession` не успевает, `push()`
  приостанавливает fiber фида, сокет перестаёт читаться, TCP-окно закрывается
  и биржа притормаживает. Ничего не теряется и не копится без предела.
- **Детекция зависшего фида.** Молчащее соединение дольше `staleAfterSeconds`
  отменяет `receive()`; фид отличает «запрошена остановка» от «фид завис» и
  переподключается через `reconnectDelay`.
- **Декодер — единственная граница JSON.** `JsonTickDecoder` (собственный
  строчный формат библиотеки) и примеры биржевых декодеров разбирают payload с
  `JSON_THROW_ON_ERROR`, возвращают `null` для heartbeat'ов и подтверждений и
  ОБЯЗАНЫ брать биржевой timestamp из сообщения — никогда локальное время.
  `SbeTickDecoder` — бинарная альтернатива: один `unpack()` на кадр, без
  промежуточных объектов, в 3–5 раз дешевле JSON (`DecoderBench`).
- Фид никогда не завершает очередь: её делят несколько фидов, и завершает её
  оркестратор, когда остановились *все*.

## 3. Оркестратор: несколько фидов, одна очередь

`IngestOrchestrator::start()` запускает по fiber'у на фид, возвращает
`IngestHandle` с очередью и `DeferredCancellation` и завершает очередь, когда
закончились все насосы (`awaitAll`). Забытый `complete()` — классическая
ошибка AMPHP: `foreach ($queue->iterate())` в сессии никогда не вернётся.

## 4. ReorderBuffer как Pipeline-оператор

Внеочередные измерения — норма при нескольких площадках. Буфер держит окно
`W` нс, сортирует внутри него по `timestampNs` и отдаёт всё, что старше
`watermark − W`:

```php
foreach ((new ReorderBuffer(windowNs: 2_000_000))->apply($queue->iterate()) as $m) {
    $inbox->push($m);
}
```

`W` — размен задержки на точность: 1–5 мс в колокейшене, 50–200 мс на
розничных API. Измерение, пришедшее позже `W`, всё равно доходит до фильтра с
`dt < 0` и обрабатывается политикой `OutOfSequencePolicy` сессии.

## 5. FilterSession — единственный владелец

`Infrastructure\Async\FilterSession` читает `Measurement | Command` из своего
inbox и выполняет их строго по порядку:

- `Measurement` → проверка на внеочередность → **атомарный шаг** (`predict` +
  `correct`, без `await` между ними) → монитор → каждый `snapshotEvery`-й тик
  в очередь снапшотов кладётся `StateSnapshot` (этот push может приостановить
  fiber; состояние фильтра к этому моменту уже согласовано).
- `SnapshotRequest` → завершает свой future состоянием *ровно после того
  измерения, которое предшествует запросу в inbox* — линеаризованные снапшоты.
- `CorporateAction` (`Split`, `Dividend`, `Rebalance`, `Reset`) → применяется
  между шагами, в порядке поступления.

Политики внеочередных измерений: `Drop` (по умолчанию, со счётчиком),
`Retrodict` (точная одношаговая ретродикция), `Fail` (бросает исключение —
для тестов и строгих конвейеров).

**Батчинг (§6.5 проектного документа), два уровня.**

*Сторона продюсера — та, что решает.* `MeasurementBatcher::pump($source, $inbox)`
вычерпывает источник вспомогательным fiber'ом и кладёт всё, что накопилось
за время предыдущего push, ОДНИМ элементом-массивом; сессия принимает
`array<Measurement>` штатно. Пара `Queue::push/iterate` (~1 мкс) платится
тогда за батч, а не за тик: измеренные накладные расходы loop на тик падают с
0.93 мкс до 0.0 мкс (`EventLoopOverheadBench`). Под нагрузкой батчи растут к
`maxBatch`; при низкой нагрузке батч — одно измерение, и задержка не меняется.
Команды пересылаются по одной на своей позиции в потоке, поэтому
линеаризация снапшотов сохраняется.

*Сторона потребителя.* При `batchSize > 0` сессия сама вычерпывает inbox в
массив и обрабатывает его за одно пробуждение. Это амортизирует только
переключение fiber'а владельца (~0.1–0.25 мкс на тик); поэлементная цена
очереди остаётся — именно поэтому существует батчер на стороне продюсера.

Оба уровня сохраняют back-pressure (вычерпывающие fiber'ы останавливаются на
пределе) и порядок.

```php
$session = new FilterSession($filter, $inbox, $snapshots, $monitor, snapshotEvery: 100);
$final = $session->start();          // Future<StateSnapshot>, завершается вместе с inbox

async(static function () use ($ordered, $inbox): void {
    (new MeasurementBatcher(256))->pump($ordered, $inbox);   // $ordered: выход ReorderBuffer или любой iterable
    $inbox->complete();
});
```

## 6. Часовой тик: прогноз без измерений

Когда данные прекращаются (ночь, остановка торгов), `P` должна честно расти,
а потребители — видеть расширяющуюся неопределённость. `BarClock` использует
`Amp\Interval` с `weakClosure` (иначе интервал держит часы, а часы —
интервал: утечка) и кладёт `Measurement::blind(ts)` в inbox.

Timestamp берётся из абстракции `Clock` (`SystemClock::realtimeNs()`,
`ManualClock` в тестах) — наносекунды `CLOCK_REALTIME`, никогда `hrtime()`,
потому что биржевые timestamp'ы — это календарное время, и их нужно
сравнивать между собой.

## 7. Раздача оценок: WebSocket-шлюз и HTTP

`SnapshotBroadcaster` читает очередь снапшотов и вызывает
`WebsocketClientGateway::broadcastText()` с выводом `SnapshotSerializer` —
неблокирующе, медленный клиент не тормозит остальных. Push-only обработчик
`StateWebsocketHandler` дренирует входящие кадры (правило про дедлок буфера).
`HttpStateHandler` обслуживает `GET /state`: он вызывает
`$session->requestSnapshot()->await()` — граница I/O, где `await` уместен.

## 8. Персистенция снапшотов

`FilePersister` пишет через временный файл и `File\move()` (атомарная замена);
`RedisPersister` хранит последнее состояние под ключом. Восстановление —
`FilterFactory::fromConfig($model, $config, $snapshot)`: `x, P` и
`lastTimestampNs` восстанавливаются, а первый шаг после рестарта делает
прогноз на реальный пропущенный интервал, так что `P` честно раздувается.

## 9. Масштабирование на ядра: amphp/parallel

Один процесс PHP — одно ядро. Единица распределения — **группа инструментов с
общим состоянием** (одна корзина ETF, одна пара, один мультивенью-актив);
группы независимы и могут жить в разных процессах.

`FilterWorkerTask` владеет одним фильтром в воркере: он пересобирает модель
*внутри* `run()` из сериализуемого конфига (никаких замыканий и открытых
соединений через границу), получает **батчи** сырых тиков через IPC-канал,
выполняет тот же атомарный `stepRaw()` и отправляет компактные снапшоты
каждые `snapshotEvery` тиков. Поток завершается сигнальным `null`; задача
возвращает финальный снапшот.

`WorkerSession` — родительская сторона: `Batcher` группирует измерения (по
умолчанию 256), fiber-приёмник перекладывает компактные снапшоты в `Queue`.

**Стоимость IPC.** Один `Channel::send` — 20–50 мкс, в десять раз дороже шага
фильтра. Отсюда батчи по 64–512 тиков (`IpcBench`: 26 мкс/тик при батче 1,
2.3 мкс при 64 и больше), редкие снапшоты и отказ от воркера вообще для групп
меньше ~5 тыс. тиков/с.

**Детерминизм движка.** Результаты воркера побитово совпадают с
внутрипроцессными только если родитель и дети работают с одинаковой
конфигурацией движка. Стандартный `workerPool()` запускает детей с голым
бинарником и php.ini — возможно, с включённым Xdebug, без JIT или с другим
режимом JIT. Стройте продакшен-пулы через `WorkerPools::likeParent($limit)`:
он повторяет каталог расширений, сами расширения, флаги JIT, assertions и
лимит памяти родителя. См. ADR-007 про ошибки компиляции JIT в PHP 8.2/8.3,
которые библиотека обходит, и ADR-008 про общий сегмент OPcache на Windows.

## 10. Параллельная калибровка

Каждая точка симплекса — независимый прогон фильтра по одной и той же
истории, идеальный fan-out. `LikelihoodTask` получает *путь* (воркеры читают
историю один раз и кэшируют её на процесс) или список тиков в памяти для
небольших случаев; `ParallelCalibrator` отправляет каждый батч кандидатов
оптимизатора одновременно и ждёт их вместе. Один симплекс Нелдера–Мида даёт
лишь 4 точки на итерацию, что ограничивает ускорение на уровне 2–3×
независимо от размера пула; `MultiStartNelderMead(starts: K)` ведёт K
симплексов синхронно и выдаёт 4K точек за раунд — 4.5× по числу вычислений в
секунду на 8 воркерах в `CalibrationBench` плюс устойчивость к локальным
оптимумам. Независимые вычисления масштабируются по числу физических ядер
(`ScalingBench`).

Файловый ввод-вывод внутри воркера намеренно использует **блокирующий**
драйвер файловой системы: стандартный `ParallelFilesystemDriver` породил бы
вложенный пул воркеров внутри каждого воркера (медленный старт, зависшие
дети, из-за которых родитель не завершается на Windows), а выделенному
воркеру всё равно нечем заняться, пока он читает.

## 11. Бэктесты из файлов

`HistoryReader::stream()` читает JSON-строки (или CSV) через `Amp\File` и
`splitLines`, распаковывая `.gz` на лету; `readAll()` — для небольших историй.
Тики могут нести строки наблюдения на каждый тик (`rows`), чтобы
регрессионные модели с меняющейся `H_t` точно переходили границу процесса.
Для сглаживания траектория пишется в `FilterTrajectory` и сбрасывается в
`TrajectoryFile` при превышении лимита памяти.

## 12. Корректная остановка

Порядок важен: остановить источники, завершить inbox, дождаться владельца,
сбросить персистер.

```php
$signal = trapSignal([\SIGINT, \SIGTERM]);   // ext-pcntl; на Windows — обычный EventLoop::run()
$handle->stop();                             // фиды выходят из receive()
$inbox->complete();                          // сессия дообрабатывает буфер и возвращается
$final = $sessionFuture->await();            // финальный снапшот
$persister->flush();
```

Обратный порядок теряет тики, которые ещё лежали в буфере.

## 13. Тестирование асинхронного слоя

Все асинхронные тесты наследуют `Amp\PHPUnit\AsyncTestCase` и запускаются с
`zend.assertions=1`:

- `FilterSessionTest` — перемешанные тики через `ReorderBuffer` дают монотонный
  `dt` и тот же результат, что упорядоченный прогон; снапшот, запрошенный
  между двумя тиками, отражает ровно первый из них; батчевая и обычная сессии
  побитово совпадают.
- `MeasurementBatcherTest` — массивы измерений в inbox дают то же состояние при
  значительно меньшем числе элементов очереди, команды сохраняют позицию.
- `WebsocketFeedTest` — замолчавшая мок-биржа (`tests/Support/MockExchangeServer`)
  вызывает переподключение; остановка прерывает ожидающий `receive`.
- `IngestOrchestratorTest` — очередь завершается, когда остановились все фиды.
- `WorkerTest` (`@group slow`) — результаты батчевого IPC побитово равны
  внутрипроцессным.
- `BarClockTest` — слепые шаги увеличивают неопределённость.
- `PersistenceTest`, `HttpStateHandlerTest`, `TrajectoryFileTest`.

## 14. Чеклист типовых ошибок AMPHP

| Ошибка | Как проявилась бы здесь |
|---|---|
| `await()` вне fiber'а | `requestSnapshot()->await()` из синхронного бенчмарка |
| блокирующий I/O в loop | `file_put_contents` в персистере; `usleep` в бэктесте «для реалистичности» |
| не вызван `Queue::complete()` | `FilterSession::run()` никогда не выходит из своего `foreach` |
| `Channel::receive()` в `while ($x = …)` | воркер падает с необработанным исключением при штатном завершении (нужен сигнальный null) |
| стрелочная функция захватывает по значению | счётчик обработанных тиков навсегда остаётся 0 |
| `Interval` без `weakClosure` | `BarClock` не собирается GC, процесс течёт |
| `hrtime()` вместо биржевого времени | `dt` не соответствует данным, `Q` неверна |
| `await` внутри шага | порча состояния при конкурентных запросах снапшота |
| вложенные пулы воркеров (`Amp\File` внутри воркера) | старт по 10 секунд, родители, которые не завершаются |
